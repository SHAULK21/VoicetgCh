# Telegram Voice Reader

Бот Telegram Serverless + мобильная Mini App + Android-компаньон для чтения уведомлений с погашенным экраном.

## Что работает где

| Режим | Откуда берётся текст | Озвучка | Когда работает |
|---|---|---|---|
| Mini App | Посты каналов с ботом, ручные/периодические проверки публичных страниц | Gemini или системный голос браузера | Пока панель открыта и устройством разрешён звук |
| Telegram-бот | События `channel_post`, команды | Текстовые уведомления и управление панелью | Serverless реагирует на события Telegram |
| Android-компаньон | Уведомления Telegram с выбранными точными заголовками | Системный TTS Android | После ручного запуска службы, включая погашенный экран |

Бот не заставляет Telegram автоматически проигрывать присланные голосовые. Непрерывное чтение новых уведомлений на телефоне выполняет Android-компаньон. У него нет разрешения INTERNET, нет токенов бота и нет доступа к аккаунту Telegram. Системный движок TTS может использовать онлайн-голоса; для автономности установите офлайн-голос.

## Развёртывание Telegram Serverless

Нужен Node **22.13+**, рекомендуется 24 LTS. В BotFather → нужный бот включите Serverless.

```sh
npm ci
npm test
npm run lint
npm run build
npx tgcloud login
npx tgcloud push
npx tgcloud migrate
```

В `login` вводится **CLI Access token** из BotFather → Serverless → CLI Access, а не HTTP API Token. Никогда не коммитьте `.tgcloud`, `.env` и ключи. `push` публикует модули и `dist`; `migrate` создаёт таблицы. При первом запуске выполните оба действия до проверки команд.

Адрес Mini App, выданный `push`, настройте в BotFather как Main Mini App/кнопку меню. Откройте её из Telegram. Клиент вызывает `Telegram.WebApp.Serverless.call('reader',…)`; платформа проверяет initData. Владелец определяется по `ctx.initData.user.id`, а не по переданному из интерфейса ID. Само скачивание статической страницы не открывает доступ к данным.

Для Gemini добавьте свой API key в поле панели. Ключ хранится в отдельной серверной таблице для пользователя и не возвращается в state/feed. По умолчанию используется бесплатный системный голос. Скорость и тон регулируются для системного голоса; Gemini использует выбранный голос и стиль. В панели есть удаление ключа.

Команды в личном чате: `/start`, `/help`, `/add слово`, `/remove слово`, `/list`, `/clear`, `/voice Kore`, `/night on`, `/night off`, `/channel add @username`, `/channel remove @username`, `/channels`, `/check`, `/test текст`, `/status`. Команды с `@имя_бота` поддерживаются. Команды из групп не меняют личные настройки.

Добавьте бота в нужный публичный канал для событий `channel_post`. Сначала добавьте этот канал в личный список через панель или команду. Чужие публичные страницы доступны для `/check` и периодической проверки в видимой панели. Это не обещание Serverless cron: при закрытой панели парсер сам не запускается. Для фонового режима телефона подпишитесь на нужные каналы обычным Telegram и включите их уведомления.

Первая проверка публичной страницы устанавливает курсор без чтения старых публикаций. За один запрос проверяются до 5 каналов; следующие запросы берут самые давно проверенные. Максимум 20 каналов, 2 проверки/минуту на пользователя. HTML-источник может пропускать старые посты: в статусе показывается предупреждение. Изменения уже существующего поста в Bot API обновляют ленту без повторной тревоги. Приватные каналы без username в облачную ленту пока не подключаются; их уведомления можно читать компаньоном на своём телефоне.

## Android: установка и запуск

Готовый debug APK собирается workflow **Android APK** и доступен в его artifacts как `voice-reader-debug`. Для публикации обновлений пользователям нужна постоянная release-подпись; debug-сборка предназначена для личной проверки.

Локальная сборка: Android SDK 35, JDK 17, затем:

```sh
cd android
./gradlew testDebugUnitTest lintDebug assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

1. Установите APK. Откройте Voice Reader, разрешите доступ к уведомлениям через кнопку. Android выдаёт доступ ко всем уведомлениям; код компаньона отбирает только официальные пакеты Telegram/Telegram X и точные выбранные заголовки.
2. В Telegram включите уведомления нужных каналов и предпросмотр текста. Отключённые/скрытые уведомления компаньон получить не сможет. Текст может быть сокращён самим Telegram — это не полный клиент Telegram.
3. В APK 1.1.1 нажмите **«Обрати зі сповіщень Telegram»** и выберите нужный канал из активных уведомлений. Или введите **точные заголовки уведомлений** каналов, каждый с новой строки. Вверху показаны реальное соединение со службой уведомлений, последний заголовок и причина пропуска. При разрыве соединения используйте «Перепідключити сповіщення». Временная потеря аудиофокуса автоматически возобновляет чтение после возврата звука; ручная пауза сохраняется. Кнопка запуска также снимает ручную паузу. Можно импортировать `voice-reader-settings.json` из панели; после импорта проверьте названия. Непроверенный `@username` из панели может потребовать замены на фактическое название. Пустой список ничего не читает. Сопоставление по заголовку не определяет тип чата: не выбирайте заголовки, совпадающие с личными чатами.
4. Задайте ключевые слова, скорость, тон и ночной режим. Установите **украинский голос** в системных настройках TTS и нажмите «Перевірити голос і ключові слова». Приложение предпочитает установленный офлайн-голос украинского языка; если украинского голоса нет, показывает инструкцию вместо перехода на другой язык. Панель также использует украинское произношение. Автоматического перевода исходных постов нет.
5. Нажмите **«Запустити читання»** при открытом приложении. Разрешите уведомления Android. Затем экран можно погасить; служба остаётся видна в уведомлениях с кнопками паузы и остановки.
6. На Poco/Xiaomi в настройках приложения выберите батарею **«Без ограничений»**, разрешите фоновую работу. В APK 1.2.2 после обычного завершения процесса Android может восстановить foreground-службу (START_STICKY), и включённое чтение не сбрасывается из onDestroy. При отключении слушателя отправляется один отложенный запрос переподключения. Кнопка остановки и ошибка установленного голоса выключают чтение явно, без автоматического возобновления. После перезагрузки/принудительной остановки службу нужно запустить вручную. HyperOS может запретить даже системное восстановление; разрешите фоновую работу и автозапуск. Последняя lifecycle-подія и состояние Android-оптимизации видны в приложении. Приложение не обходит системные настройки громкости и доступности уведомлений.

В APK 1.4.0 исправлена отдельная причина самопаузы и повторов: потеря/отказ аудиофокуса больше не переводит службу в ручную паузу. Она ждёт системное разрешение и автоматически повторяет запрос с интервалом 2–30 секунд только при наличии ожидающей озвучки; таймер не будит телефон и не удерживает CPU. Ручная пауза и остановка отменяют повторы запросов. В уведомлении автоматическое ожидание показывается отдельно от ручной паузы.

Голос сначала синтезируется в приватный временный аудиофайл, затем воспроизводится MediaPlayer: `pause/start` сохраняет точную позицию звука при прерываниях, вместо повторной постановки всего текста в TTS. Завершённые фрагменты и громкий префикс не запускаются заново. Файл удаляется после открытия проигрывателем; остатки после сбоя удаляются при следующем запуске службы. Wake lock ограничен подготовкой/воспроизведением и освобождается на ожидании звука.

Также подавляются повторные Intent-доставки и копии текста одного канала под разными ключами уведомлений в пределах 5 секунд. Два структурированных сообщения с различающимися исходными временными метками остаются разными; если источник передал только простой текст без идентификаторов, две одинаковые отдельные публикации под разными ключами за эти 5 секунд неотличимы от копии и могут быть объединены.

В APK 1.3.1 исправлены повторы при обновлении обычного текстового уведомления: изменение `when`/времени публикации при том же тексте больше не создаёт новое объявление. Общий снимок содержимого связывает переходы Plain/Inbox/MessagingStyle, чтобы смена формата не повторяла уже прочитанное. Новые сообщения MessagingStyle с отдельными временными метками продолжают читаться, даже если их текст совпал. Обычный текст звучит один раз, только найденные экстренные фразы повторяются трижды. Для простого текста без отдельных идентификаторов одинаковые последовательные посты внутри одного несмахнутого уведомления неотличимы от его обновления и пропускаются; после удаления уведомления новая доставка обрабатывается заново.

В APK 1.3.0 добавлен переключатель **«Не читати довгі повідомлення»**, включённый по умолчанию: сообщения длиннее **500 символов** пропускаются целиком, включая ключевые фразы в обоих режимах чтения. Ползунок меняет предел от 100 до 3000 символов с шагом 100; изменения сохраняются автоматически и проверяются также перед чтением очереди. Фильтр можно выключить. Сообщение ровно на границе читается; символы Unicode (включая отдельные emoji) считаются по кодовым точкам. Каждое сообщение MessagingStyle/строка InboxStyle проверяется отдельно: длинный старый пост не мешает чтению короткого нового. Пропущенные посты отмечаются обработанными и не повторяются при обновлении уведомления. В диагностике видна причина пропуска; обе проверки голоса обходят лимит длины. Это фильтр длины, а не распознавание рекламы: Telegram может передать сокращённый текст, поэтому лимит применяется только к доступной части.

В APK 1.2 доступен переключатель **«Озвучувати лише ключові фрази»**: звучат только совпавшие слова/фразы из списка, без тела сообщения; уведомления без совпадений молчат. По умолчанию переключатель выключен. Громкий акцент повторяет фразы трижды; если его выключить, фразы звучат один раз на обычной/ночной громкости.

В APK 1.2.1 громкость, ночной режим, скорость, тон и переключатели озвучки сохраняются автоматически при изменении и применяются со следующего объявления. Для каналов и текста списка фраз остаётся кнопка сохранения. «Перевірити звичайну гучність» запускает обычный тест без тревожного акцента, даже если включён режим только ключевых фраз; отдельная кнопка проверяет тревожную громкость. Ночной режим снижает громкость тела сообщения, а громкие ключевые слова используют собственный ползунок.

В полном режиме сначала звучит «Увага!» и каждое найденное ключевое слово/фраза трижды, затем исходное сообщение. Для слов и чтения есть отдельные ползунки громкости (по умолчанию 100% и 60% от медиауровня телефона) и переключатель громкого акцента. В ночном режиме слова остаются громкими, а тело сообщения читается тихо. Тревожный пост имеет приоритет в очереди. Украинский интерфейс и голос включены по умолчанию; свои слова сохраняются при обновлении. Системная громкость не увеличивается тайно. Очередь ограничена 20 уведомлениями; переполнение отмечается в статусе. Групповые summary-уведомления игнорируются. Если уведомление не смахнуто, обновление MessagingStyle `[A] → [A,B]` читает только B по идентичности отдельных сообщений. Для InboxStyle сравнивается последовательность строк: `[A,B] → [B,C]` читает только C; неизменившийся список молчит. В памяти хранятся только хеши последних списков, при переподключении базовый снимок восстанавливается из активных уведомлений. Если источник выдаёт лишь один неструктурированный текст вместо сообщений/строк, точное разделение старого и нового содержимого невозможно; читается доступный текст этого источника. Текст уведомлений не записывается на диск; для диагностики локально сохраняются последний заголовок и время получения. Новые доставки не отбрасываются по времени исходного поста: уже видимые при запуске уведомления отмечаются как исходный снимок. Wake lock удерживается только во время подготовки/воспроизведения с таймаутом; ожидание аудиофокуса не удерживает его, аудиофокус освобождается после озвучки.

### Проверка на телефоне перед постоянным использованием

- Запустите службу, заблокируйте экран и отправьте новый пост в выбранный канал с другого устройства. Убедитесь, что слышен голос и имя канала совпадает с allowlist.
- Повторите с триггером и ночным режимом; проверьте отсутствие двойного чтения при обновлении уведомления.
- Оставьте телефон заблокированным 15–30 минут и проверьте ещё один пост через Wi-Fi/мобильную сеть.
- Проверьте наушники, входящий звонок, паузу/остановку, отключение предпросмотра и перезапуск приложения.

Сборка и unit-тесты не заменяют этот тест: поведение Telegram-уведомлений и энергосбережения зависит от устройства. Не используйте это приложение как гарантированную систему экстренного оповещения.

## Локальная разработка / резервный Node-сервер

```sh
cp .env.example .env
npm ci
npm run dev
```

Панель: `http://127.0.0.1:3000`. `ALLOW_LOCAL_DEV=true` разрешает только loopback-доступ к тестовому пользователю 1, и только вне production. Запуск на другом интерфейсе сам по себе не открывает этот обход удалённым клиентам. SQLite: `data/reader.sqlite` (включая WAL), каталог не входит в Git. Сервер требует Node с `node:sqlite`.

В production Node-резерв требует `NODE_ENV=production`, `BOT_TOKEN` и `WEBHOOK_SECRET` длиной не меньше 32 символов. Webhook `/api/bot/webhook` принимает только `X-Telegram-Bot-Api-Secret-Token`, совпадающий с секретом; этот же secret_token задаётся при настройке webhook Bot API. За TLS отвечает хостинг/прокси. API Mini App требует подписанные initData, не старше часа. В Serverless webhook управляет платформа: вручную `deleteWebhook`/`getUpdates` не вызываются.

## Обновления и данные

После правок: `npm ci && npm test && npm run lint && npm run build`, затем `npx tgcloud diff`, `npx tgcloud push`, при изменении schema — `npx tgcloud migrate`. Новая версия Android требует обновления APK. Настройки Android импортируются вручную, постоянной синхронизации с Mini App нет.

Посты защищены уникальностью `(user_id, source_key)`, настройки — revision/CAS. Доставка уведомления Bot API имеет состояния pending/sent/uncertain. При обрыве связи после отправки uncertain не пересылается автоматически, чтобы не дублировать тревогу; `/status` показывает количество. Абсолютная exactly-once доставка внешним API не обещается. История ограничена 200 доставленными записями на пользователя; локальные проверки не отправляют Telegram-уведомления сами по себе.

Платные запросы TTS ограничены на пользователя: 3 запуска/минуту и 100 обращений к провайдеру/сутки, включая каждый сегмент длинного текста. Длинный текст делится без обрезания. При ошибке Gemini панель показывает причину и использует системный голос, если доступен. Проверки TTS в CI используют заглушки, настоящие ключи не нужны.
